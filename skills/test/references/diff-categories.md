# 差分を言語化するカテゴリ

オーバーレイ/ディファレンス/サイドバイサイド画像から目視できる差分を整理するための観点集。
各カテゴリに該当する差分が「なかった」場合でも、レポートでは必ず「差分なし」と明記してカテゴリの見落としを防ぐ。

差分を書くときは必ず以下の5要素を含める。

- 対象: どの要素か（セクション名、ラベル、ボタン名、ロールなど）
- 事実: A（reference）ではどうで、B（target）ではどうか（両方の状態を併記）
- 量: どの程度ずれているか（px数、% 値、色の濃淡など、目視できる範囲での概算でよい）
- 原因候補: 比較パターンに応じて、CSS プロパティ・設定・コミットなど原因の見当（断定せず「〜の可能性」と書く）
- 優先度: 高 / 中 / 低

比較パターンごとの「A / B」のラベル例:

- Figma vs 実装: A=Figma / B=実装
- 本番 vs ローカル: A=本番 / B=ローカル
- リファクタ前後: A=リファクタ前 / B=リファクタ後
- ブランチ比較: A=main / B=feature-xxx

## 色

背景色、文字色、ボーダー色、アクセント色、グラデーション、透明度。
difference画像で白く光る領域が面として広がっていれば背景色の差、文字の輪郭だけが光れば文字色の差を疑う。

チェック観点

- ブランドカラー / アクセント色が正しい濃度か
- ダークモード・ライトモードが取り違えられていないか
- 透明度（alpha）が Figma と同じか
- グラデーションの方向と停止位置
- hover でしか見えない色が撮影時に出ていないか

## タイポグラフィ

フォントサイズ、行間、字間、ウェイト、書体、テキスト整列、大文字小文字、改行位置。
overlay画像で文字輪郭が二重にずれて見えたら、サイズかウェイトか行間を疑う。

チェック観点

- 見出しと本文のサイズスケール
- 太さ（Bold / Medium / Regular）の取り違え
- 行間（leading）の広狭
- letter-spacing の付け忘れ / 付けすぎ
- 書体が Web フォント読み込み前のフォールバックになっていないか
- 中央揃え / 左寄せの取り違え
- 改行位置の違い（文章量は同じでも折り返しが違うと印象が変わる）

## 余白

padding、margin、gap、セクション間スペース、カード内の余白、アイコンと文字の間隔。
overlay画像で似た要素が上下にずれて見える場合はまず余白を疑う。

チェック観点

- セクションの上下マージン（ヘッダー/フッター含む）
- カード・ボタンの内側余白
- フォーム要素間の縦ギャップ
- アイコンと文字の横ギャップ
- レスポンシブで余白値が切り替わっていない可能性

## 配置とレイアウト

整列、flex-direction、justify / align、グリッドの列数、要素の絶対位置。
side-by-side画像で要素の登場順や並びが違えばここ。

チェック観点

- 左寄せ / 中央揃え / 右寄せ
- 縦積み / 横並びの切り替え失敗
- 2カラムが1カラムになっていないか
- アイコンが文字の左にあるべきところ右に来ていないか
- absolute 指定のズレ
- z-index の前後関係（影やオーバーレイの重なり）

## サイズ

幅、高さ、アスペクト比、最大幅（max-width）、コンテナ幅。
overlay画像で輪郭が1本ずれていればサイズの違い。

チェック観点

- ボタン / カード / 画像の横幅
- 高さ固定の要素（ヘッダー、ヒーロー）
- コンテナの max-width（画面幅フルか中央寄せか）
- 画像のアスペクト比（潰れ・引き伸ばし）
- ロゴのサイズ

## 要素の有無・構成

欠落、過剰、順序違い、数の違い。
side-by-side画像で一目で分かる。

チェック観点

- ナビ項目の数
- フッターリンクの欠落
- バッジ、ラベル、注釈の欠落
- 「新着」などの装飾バッジが実装側にだけ残っている
- 表示条件付き要素（会員限定バナー等）の現れ方

## 画像・アイコン

解像度、形状、トリミング、alt 表示、プレースホルダーの出方。
アイコンは `currentColor` の継承不整合で色が合わないパターンに注意。

チェック観点

- 画像が仮画像のままになっていないか（本件のチェック対象か要確認）
- アイコンの線幅（stroke）
- アイコンの塗り / 線（fill vs stroke の取り違え）
- 画像の object-fit（cover / contain）
- 角丸の適用有無

## 装飾

角丸、ボーダー、シャドウ、グラデーションボーダー、アウトライン。

チェック観点

- border-radius（ピル型 / 角丸 / 直角）
- ボーダーの色と太さ
- box-shadow の有無・濃度・広がり
- フォーカスリング（撮影時に focus が残っていないか）

## 状態

撮影時に hover / focus / active / 展開 / 折り畳み / エラー / 成功などの状態が A と B で揃っているか。
ここの差分はバグではなく「撮影条件違い」であることが多いので、優先度は低〜中で扱う。

チェック観点

- hover色が残ったまま撮影していないか
- アコーディオンの開閉状態
- ドロワー / モーダルの開閉
- フォームのエラー表示状態
- ローディングスピナーが入り込んでいないか

## 差分として扱わないもの（除外項目）

以下は原則「差分なし」として扱い、別途コメントだけ残す。

- プレースホルダー画像（まだ仮画像のもの）
- ダミーテキスト（Lorem ipsum 等）
- 動的コンテンツ（投稿一覧、ニュース、日付）
- フォントのアンチエイリアス由来の微小な色差
- スクロールバーの有無
