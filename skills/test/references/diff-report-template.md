# 差分レポートのテンプレート

`/tmp/product-test/ui-diff/<RUN>/report.md` として書き出す。以下をそのままコピーして埋める。

比較パターンごとの A / B ラベル例:

- Figma vs 実装: A=Figma / B=実装
- 本番 vs ローカル: A=本番 / B=ローカル
- リファクタ前後: A=リファクタ前 / B=リファクタ後
- ブランチ比較: A=main / B=feature-xxx

```markdown
# UI Diff Review レポート

## 対象

- 比較目的: {比較の目的を1行で}
- ソース A（reference）: {ラベル} - {URL / node-id / PNG パス}
- ソース B（target）: {ラベル} - {URL / node-id / PNG パス}
- ビューポート: PC 1920 / SP 375
- 撮影日時: {timestamp}

## 前処理

比較画像を生成する際に使った overlay-compose の前処理オプションを記録する。何も指定していない場合は「なし」と書く。

| ビューポート | --offset-y | --crop-top | 理由                                             |
| ------------ | ---------- | ---------- | ------------------------------------------------ |
| PC           | 0          | 0          | なし                                             |
| SP           | 60         | 0          | B のみクッキーバーが 60px 表示されていたため整列 |

HTMLビューアを生成した場合は `/tmp/product-test/ui-diff/<RUN>/index.html` へのパスもここに書く。

## 生成画像

- PC overlay: /tmp/product-test/ui-diff/<RUN>/pc-overlay.png
- PC difference: /tmp/product-test/ui-diff/<RUN>/pc-difference.png
- PC side-by-side: /tmp/product-test/ui-diff/<RUN>/pc-side-by-side.png
- SP overlay: /tmp/product-test/ui-diff/<RUN>/sp-overlay.png
- SP difference: /tmp/product-test/ui-diff/<RUN>/sp-difference.png
- SP side-by-side: /tmp/product-test/ui-diff/<RUN>/sp-side-by-side.png
- HTML ビューア: /tmp/product-test/ui-diff/<RUN>/index.html（生成した場合）

## 差分メトリクス（参考値）

| ビューポート | 比較領域  | 平均差分 (0-255) | 最大差分 |
| ------------ | --------- | ---------------- | -------- |
| PC           | 1920x7354 | 19.1             | 255      |
| SP           | 375x6200  | {sp_mean}        | {sp_max} |

メトリクスは参考値。低くても色だけ揃って配置がズレている場合があるため、必ず目視の言語化を優先する。

## サマリ

- 優先度「高」: {高件数}件
- 優先度「中」: {中件数}件
- 優先度「低」: {低件数}件
- 注目すべき3点:
  1. {重要差分1}
  2. {重要差分2}
  3. {重要差分3}

## 差分（PC）

### 色

- [高] 対象: プライマリボタン
  A: #0F5FAB
  B: #1E73BE
  量: 目視で明度が約10%明るい
  原因候補: --color-primary の値違い、または hover 色の誤適用
  参考画像: pc-difference.png のボタン周辺が白く光っている

### タイポグラフィ

- [中] 対象: ヒーロー見出し
  A: font-weight 700
  B: 600相当に見える
  量: 輪郭が約1pxぶん細い
  原因候補: font-weight の指定違い、Web フォント未読込、環境差によるフォールバック
  参考画像: pc-overlay.png の見出し部分で二重輪郭

### 余白

- 差分なし

### 配置とレイアウト

- [高] 対象: 3カラムのカード
  A: 横並び3列
  B: 2列 + 1列で折り返している
  量: 1020px以下で想定より早く折り返している
  原因候補: メディアクエリのブレークポイント違い、flex-basis の計算違い、または環境差で古い CSS が配信されている可能性
  参考画像: pc-side-by-side.png 右側

### サイズ

- 差分なし

### 要素の有無・構成

- [高] 対象: フッターの「採用情報」リンク
  A: あり
  B: なし
  量: 1項目欠落
  原因候補: ナビゲーション配列に未追加、またはリリース前のコミットが B 側に入っていない
  参考画像: pc-side-by-side.png フッター部

### 画像・アイコン

- [低] 対象: お知らせセクションのサムネイル
  A: 実画像
  B: 仮画像
  量: 参考まで
  除外項目として扱う（本件のチェック対象外）

### 装飾

- [中] 対象: カードのシャドウ
  A: box-shadow 0 8px 24px rgba(0,0,0,.08)
  B: shadow なし
  量: 影が完全に欠落
  原因候補: shadow クラスの付け忘れ、Tailwind のビルド取りこぼし

### 状態

- 差分なし

## 差分（SP）

（PC と同じフォーマットで記載）

## 除外項目（差分として扱わない）

- お知らせセクションのサムネイル画像（仮画像）
- 日付や件数の差（動的コンテンツ）
- プレースホルダーテキスト

## 次のアクション候補

- [ ] --color-primary を #0F5FAB に統一
- [ ] フッターに「採用情報」リンクを追加
- [ ] カードに box-shadow を付与
- [ ] 3カラムのブレークポイントを見直す（1080 → 1200 へ）
- [ ] 詳細な計算値が必要なら figma-check スキルに引き継ぐ
```

## 書き方のコツ

1件の差分は5〜8行に収める。長くなりそうな場合は複数件に分ける。

「ズレている」「違う」といった主観だけの記述は避け、A / B それぞれの状態を併記する。量は px/%/色相のレベルで書く。見積もれない場合は「目視で小さめ/大きめ」と明記し、pixel 単位の断定は避ける。

カテゴリ内に差分がないときは必ず「差分なし」と書く。空欄にするとチェック漏れと区別できない。

原因候補は比較パターンに応じて書き分ける:

- Figma vs 実装: CSS プロパティ名まで具体化する（「padding が違う」ではなく「padding-top の違い」まで踏み込む）
- 環境 / ブランチ比較: 疑うのは CSS ではなく、環境変数・ビルド設定・キャッシュ・データ差・フィーチャーフラグなどの可能性
- いずれのパターンでも断定はせず「〜の可能性」と書く

優先度の目安

- 高: レイアウトが崩れている / 要素が欠落している / ブランドカラーが違う
- 中: 余白や色味がずれている / サイズがわずかに違う / シャドウや角丸の差
- 低: アンチエイリアス起因の差 / 撮影時状態差 / 仮画像や動的コンテンツに起因する差

## 複数ページ版テンプレート

複数ページを一括比較した場合は、ページ別のサマリ表を先頭に置き、要注意ページだけ詳細を書く。全ページに9カテゴリ全部書こうとすると膨大になるため、これで総量を抑える。

```markdown
# UI Diff Review レポート（複数ページ）

## 対象

- 比較目的: 本番 vs ローカル全ページチェック
- ソース A（reference）: 本番 https://prod.example.com
- ソース B（target）: ローカル http://example.localhost
- ビューポート: PC 1920 / SP 375
- 対象ページ: top, about, news, news-detail, product, contact
- 撮影日時: 2026-04-24 14:30

## 生成物

- HTML ビューア: /tmp/product-test/ui-diff/<RUN>/index.html
- ページ別画像: /tmp/product-test/ui-diff/<RUN>/<page>-<viewport>-{overlay,difference,side-by-side}.png

## ページ別サマリ

| ページ      | PC 優先度 | SP 優先度 | 状態     | 主な差分                              |
| ----------- | --------- | --------- | -------- | ------------------------------------- |
| top         | 高        | 高        | 要修正   | ヒーロー画像の高さ違い、3カラム折返し |
| about       | 低        | 低        | OK       | 軽微な余白差のみ                      |
| news        | 中        | 中        | 確認要   | カードサイズが SP で異なる            |
| news-detail | -         | -         | 差分なし | -                                     |
| product     | 中        | 高        | 要修正   | CTA ボタンが SP で欠落                |
| contact     | 低        | 低        | OK       | 動的プレースホルダーのみ              |

## 前処理

| ページ | --offset-y | --crop-top | 理由                    |
| ------ | ---------- | ---------- | ----------------------- |
| top    | 60         | 0          | B のみクッキーバー 60px |
| その他 | 0          | 0          | なし                    |

## 要注意ページの詳細

### top （優先度: 高）

#### 色

- 差分なし

#### タイポグラフィ

- [中] 対象: ヒーロー見出し
  A: font-weight 700
  B: 600相当に見える
  量: 輪郭が約1pxぶん細い
  原因候補: Web フォント読み込み順、または font-weight 指定違い

#### サイズ

- [高] 対象: ヒーロー画像の高さ
  A: 600px
  B: 480px相当
  量: 120px 低い
  原因候補: aspect-ratio の差、またはローカルの画像サイズが本番と違う
  参考画像: top-pc-overlay.png

#### 配置とレイアウト

- [高] 対象: 3カラムのカード
  A: 横並び3列
  B: 2列 + 1列で折り返している
  量: 1020px 以下で想定より早く折り返し
  原因候補: CSS 古いビルドが配信されている可能性
  参考画像: top-pc-side-by-side.png

（他のカテゴリは差分なし）

### product （優先度: 高）

（同じフォーマットで記載）

### news （優先度: 中）

（同じフォーマットで記載）

## 差分が軽微だったページ

- about: 全カテゴリで差分なし、または目視できないレベル
- news-detail: 差分なし
- contact: 動的プレースホルダーのみ、実差分なし

## 除外項目（差分として扱わない）

- お知らせ一覧の日付や件数（動的コンテンツ）
- プレースホルダー画像
- A/B テスト分岐で出る要素

## 次のアクション候補

- [ ] top: ヒーロー画像のサイズ指定を本番に合わせる
- [ ] top: 3カラムのブレークポイントを 1200 に見直す
- [ ] product: SP で CTA ボタンが欠落している原因を調査
- [ ] news: SP のカード max-width を揃える
- [ ] ローカルビルドを最新版に更新して再比較
```

## 報告メッセージのサマリ例

レポートファイルとは別に、チャットへ流す要約は次の形で書く。

```
UI Diff Review 完了（{比較目的}）

PC / SP の3枚セット（overlay / difference / side-by-side）を /tmp/product-test/ui-diff/<RUN>/ に生成しました。

優先度「高」3件 / 「中」2件 / 「低」1件。
特に注目したいのは以下の3点です。

1. プライマリボタンの色が A=#0F5FAB / B=#1E73BE と違う
2. 3カラムのカードが B ではブレークポイント違いで 2+1 列になっている
3. フッターの「採用情報」リンクが B 側にない

詳細レポート: /tmp/product-test/ui-diff/<RUN>/report.md
```
